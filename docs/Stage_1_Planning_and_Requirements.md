# Проект "Сервис доставки товаров"

## 1. Идея и формулирование задачи

### 1.1. Название проекта

**Сервис доставки товаров**

### 1.2. Описание идеи

Проект представляет собой информационную систему, позволяющую пользователям оформлять заказы на товары с доставкой по указанному адресу.
Пользователь может зарегистрироваться в системе, просмотреть каталог товаров, добавить необходимые позиции в корзину, оформить заказ и отслеживать его статус.
После оформления заказа система передаёт информацию о доставке курьеру. Курьер видит доступные или назначенные ему заказы, принимает заказ в работу и изменяет его статус в процессе доставки.
Администратор управляет товарами, пользователями, заказами и контролирует работу сервиса.

Таким образом, система объединяет три основных типа пользователей:
- клиент
- курьер
- администратор

### 1.3. Проблема

При организации доставки товаров необходимо координировать сразу несколько процессов:

- предоставление клиенту информации о доступных товарах
- формирование заказа
- получение адреса доставки
- расчёт итоговой стоимости
- передачу заказа курьеру
- отслеживание состояния заказа
- контроль выполненных и отменённых доставок

При отсутствии единой информационной системы эти процессы приходится выполнять через телефон, мессенджеры или несколько независимых сервисов, что усложняет обработку заказов и увеличивает вероятность ошибок.

### 1.4. Предлагаемое решение

Разработать веб-приложение, которое автоматизирует основные процессы доставки товаров.

Система должна позволять клиенту пройти полный путь: 

    Регистрация -> Каталог -> Корзина -> Оформление заказа -> Доставка -> Получение заказа

Для курьера процесс будет выглядеть следующим образом: 

    Авторизация -> Получение заказа -> Принятие заказа -> Доставка -> Завершение заказа

Для администратора: 
   
    Авторизация -> Управление товарами и пользователями -> Контроль заказов -> Просмотр состояния системы

### 1.5. Основные пользователи системы

**Клиенты** - пользователи, которым необходимо заказать товары с доставкой.

**Курьеры** - сотрудники службы доставки, выполняющие доставку заказов.

**Администраторы** - сотрудники, отвечающие за управление товарами, пользователями и заказами.

### 1.6. Ценность продукта

Для клиента сервис позволяет:

- оформить заказ онлайн
- увидеть стоимость заказа до подтверждения
- указать адрес доставки
- контролировать состояние заказа
- просматривать историю заказов

Для курьера:

- видеть назначенные доставки
- получать информацию об адресе и составе заказа
- управлять статусом доставки

Для администратора:

- централизованно контролировать заказы
- управлять каталогом товаров
- контролировать пользователей и курьеров
- получать информацию о выполненных и отменённых заказах

### 1.7. Цель проекта

Цель проекта - разработать веб-систему для автоматизации процесса заказа и доставки товаров от момента выбора товара клиентом до подтверждения выполнения доставки курьером.

Для достижения цели необходимо:

1. реализовать регистрацию и авторизацию пользователей
2. реализовать каталог товаров
3. реализовать корзину
4. реализовать оформление заказа
5. реализовать управление статусами заказа
6. реализовать интерфейс курьера
7. реализовать административный интерфейс
8. реализовать возможность онлайн-оплаты заказа с использованием стороннего платёжного сервиса
9. обеспечить хранение информации о пользователях, товарах и заказах
10. обеспечить базовую защиту данных и разграничение прав доступа

# 2. Сбор и анализ требований

## 2.1. Роли пользователей

### Клиент

- зарегистрироваться
- авторизоваться
- просматривать товары
- искать товары
- добавлять товары в корзину
- изменять количество товаров
- оформлять заказ
- указывать адрес
- просматривать свои заказы
- отслеживать их статус
- отменять заказ при определённых условиях
- выбирать способ оплаты
- оплачивать заказ онлайн
- получать информацию о результате оплаты

### Курьер

- авторизоваться
- просматривать назначенные ему заказы
- просматривать адрес доставки
- просматривать информацию о заказе
- принять заказ
- изменять статус доставки
- завершить доставку

### Администратор

- авторизоваться
- просматривать всех пользователей
- создавать и изменять товары
- удалять или деактивировать товары
- просматривать все заказы
- изменять состояние заказа
- назначать курьеров
- управлять учетными записями пользователей

## 2.2. Функциональные требования

### Авторизация и пользователи

**FR-01.** Система должна позволять пользователю зарегистрироваться.

**FR-02.** При регистрации пользователь должен указать имя, электронную почту и пароль.

**FR-03.** Электронная почта пользователя должна быть уникальной.

**FR-04.** Система должна позволять зарегистрированному пользователю авторизоваться.

**FR-05.** Система должна позволять пользователю выйти из своей учетной записи.

**FR-06.** Система должна разграничивать доступ в зависимости от роли пользователя.

### Каталог

**FR-07.** Система должна отображать список доступных товаров.

**FR-08.** Для каждого товара должны отображаться как минимум:

- название
- описание
- цена
- изображение
- наличие

**FR-09.** Пользователь должен иметь возможность открыть отдельную страницу товара.

**FR-10.** Пользователь должен иметь возможность искать товар по названию.

### Корзина

**FR-11.** Клиент должен иметь возможность добавить товар в корзину.

**FR-12.** Клиент должен иметь возможность удалить товар из корзины.

**FR-13.** Клиент должен иметь возможность изменить количество товара.

**FR-14.** Система должна автоматически рассчитывать общую стоимость товаров.

**FR-15.** Система должна отображать итоговую стоимость заказа.

### Оформление заказа

**FR-16.** Авторизованный клиент должен иметь возможность оформить заказ.

**FR-17.** При оформлении заказа клиент должен указать адрес доставки.

**FR-18.** Система должна создавать уникальный идентификатор заказа.

**FR-19.** Система должна сохранять состав заказа.

**FR-20.** Система должна сохранять стоимость заказа на момент его оформления.

**FR-21.** Клиент должен иметь возможность оплатить заказ онлайн с использованием стороннего платёжного сервиса.

**FR-22.** Система должна передавать платёжному сервису информацию, необходимую для проведения платежа.

**FR-23.** Система должна получать и сохранять результат выполнения платежа.

**FR-24.** В случае успешной оплаты система должна переводить заказ в статус "Подтверждён".

**FR-25.** В случае неуспешной оплаты система должна сообщить клиенту об ошибке и предоставить возможность повторить оплату.

**FR-26.** После оформления заказ должен получить начальный статус "Создан (ожидает оплаты)".

### Работа с заказами

**FR-27.** Клиент должен иметь возможность просматривать список своих заказов.

**FR-28.** Клиент должен иметь возможность открыть подробную информацию о заказе.

**FR-29.** Клиент должен видеть текущий статус заказа.

Основной жизненный цикл заказа:

    Создан (ожидает оплаты) -> Подтверждён -> Передан курьеру -> В пути -> Доставлен

Дополнительный переход: из статуса "Подтверждён" заказ может перейти в статус "Отменён".

**FR-30.** Клиент должен иметь возможность отменить заказ до этапа "Передан курьеру".

### Возможности курьера

**FR-31.** Курьер должен иметь возможность просматривать назначенные ему заказы.

**FR-32.** Курьер должен видеть адрес доставки.

**FR-33.** Курьер должен видеть состав заказа.

**FR-34.** Курьер должен иметь возможность принять заказ в работу.

**FR-35.** Курьер должен иметь возможность установить статус "В пути".

**FR-36.** Курьер должен иметь возможность установить статус "Доставлен".

**FR-37.** Курьер не должен иметь возможности изменять заказы, назначенные другому курьеру.

### Административные функции

**FR-38.** Администратор должен иметь возможность создавать товар.

**FR-39.** Администратор должен иметь возможность редактировать товар.

**FR-40.** Администратор должен иметь возможность удалить или скрыть товар.

**FR-41.** Администратор должен иметь возможность просматривать список всех заказов.

**FR-42.** Администратор должен иметь возможность просматривать подробную информацию о любом заказе.

**FR-43.** Администратор должен иметь возможность назначить курьера заказу.

**FR-44.** Администратор должен иметь возможность просматривать список пользователей.

**FR-45.** Администратор должен иметь возможность блокировать учетную запись пользователя.

## 2.3. Нефункциональные требования

### Производительность

**NFR-01.** Основные страницы системы должны загружаться не более чем за 3 секунды при нормальной нагрузке.

**NFR-02.** Поиск по каталогу должен выполняться не более чем за 2 секунды.

### Безопасность

**NFR-03.** Пароли пользователей не должны храниться в базе данных в открытом виде.

**NFR-04.** Доступ к административным функциям должен быть разрешён только пользователям с ролью администратора.

**NFR-05.** Клиент не должен иметь доступа к заказам других клиентов.

**NFR-06.** Курьер не должен иметь административного доступа.

### Надёжность

**NFR-07.** Система не должна терять информацию об уже созданном заказе при обновлении страницы.

**NFR-08.** Все основные ошибки должны корректно обрабатываться и отображаться пользователю в понятной форме.

### Удобство использования

**NFR-09.** Интерфейс должен быть понятен пользователю без специального обучения.

**NFR-10.** Система должна корректно отображаться на компьютерах и мобильных устройствах.

### Совместимость

**NFR-11.** Веб-приложение должно поддерживать актуальные версии основных браузеров.

## 2.4. Основные сценарии использования

### Сценарий 1. Оформление заказа

1. Клиент открывает сайт
2. Авторизуется
3. Просматривает каталог
4. Выбирает товар
5. Добавляет товар в корзину
6. Переходит в корзину
7. Проверяет товары и стоимость
8. Нажимает "Оформить заказ"
9. Вводит адрес доставки
10. Подтверждает заказ
11. Система создаёт заказ
12. Клиент получает номер заказа

### Сценарий 2. Выполнение доставки

1. Администратор открывает новый заказ
2. Назначает заказ курьеру
3. Курьер входит в систему
4. Видит назначенный заказ
5. Принимает его
6. Изменяет статус на "В пути"
7. Доставляет заказ клиенту
8. Изменяет статус на "Доставлен"

### Сценарий 3. Управление товаром

1. Администратор входит в систему
2. Открывает раздел управления товарами
3. Нажимает "Добавить товар"
4. Указывает название, описание, цену и количество
5. Сохраняет товар
6. Новый товар появляется в каталоге

# 3. MVP

## Что будет в MVP

### Клиент
- регистрация/авторизация (FR-01–06)
- каталог без поиска — просто список + карточка товара (FR-07–09)
- корзина (FR-11–15)
- оформление заказа с адресом (FR-16–20, 26)
- просмотр своих заказов и статуса (FR-27–29)

### Курьер
- весь блок как есть (FR-31–37) — без него не замкнуть цикл доставки

### Админ
- минимум: просмотр заказов, назначение курьера (FR-41–43)
- управление товарами можно делать прямо в БД/через сидинг, не как полноценный интерфейс

## Что выкинуть из MVP
- онлайн-оплата через сторонний сервис (FR-21–25) — заменим на условный статус "оплата при получении" или моковую оплату
- поиск по каталогу (FR-10)
- отмена заказа клиентом (FR-30)
- блокировка пользователей, просмотр списка пользователей (FR-44–45)
- большинство NFR (производительность, кроссбраузерность)
